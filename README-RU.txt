 Reqtificator No Master Limit
 Модифицированный Reqtificator без ограничения в 255 мастеров
========================================================================

ВЕРСИЯ
------
1.1.0 - обновление документации. Сам инструмент не изменён и
        идентичен 1.0.0; README теперь описывают реальные проблемы,
        возникающие после разбиения (части попадают в папку
        overwrite в MO2, устаревшие копии патча в других модах).
1.0.0 - первый релиз с автоматическим разбиением патча.

ЧТО ЭТО
-------
Официальный Reqtificator (из мода Requiem) падает с ошибкой
"Patch export failed! / Too many masters", если в вашей загрузке
больше 255 модов-мастеров. Ошибка носит характер жёсткого ограничения
формата плагинов Bethesda и не лечится ESL-флагами.

Эта версия Reqtificator автоматически разбивает итоговый патч
"Requiem for the Indifferent.esp" на несколько плагинов, если мастеров
не помещается в один файл. Все записи, создаваемые самим патчем,
остаются в основном плагине, поэтому порядок и целостность данных
сохраняются.

ЧТО ИЗМЕНИЛОСЬ
--------------
- Добавлен модуль PatchSplitter.cs (разбиение патча на части по 250
  мастеров в каждой).
- Изменён Backend.cs: при ошибке "too many masters" патч автоматически
  записывается частями вместо аварийного завершения.
- Сборка self-contained (.NET 5, win-x64) — не требует установленного
  .NET Framework/.NET Runtime.

КАК УСТАНОВИТЬ (Mod Organizer 2)
--------------------------------
1. Распакуйте архив.
2. Перетащите содержимое в MO2 как мод (папку с Reqtificator.bat и
   папкой Reqtificator) либо скопируйте эти два элемента внутрь
   существующего мода Requiem (в корень мода, где лежит Requiem.esp).
   При обновлении существующей установки просто замените папку
   Reqtificator\app на новую.
3. Если мод ставится отдельно от Requiem — убедитесь, что папка
   Reqtificator\ с контентом (Config, Data) видна в виртуальном Data.
4. Папку Source\ можно не копировать — это исходный код для справки.

КАК ЗАПУСКАТЬ
-------------
Как обычно: свойство-обёртка "Reqtificator" в MO2 (или ваш скрипт
запуска). Ничего настраивать дополнительно не нужно.

РЕЗУЛЬТАТ
----------
Если мастеров меньше 255 — патч запишется как раньше, одним файлом
"Requiem for the Indifferent.esp".

Если мастеров больше 255 — в логе появятся строки:
  patch exceeds the master list limit, retrying as a split patch
  wrote patch part Requiem for the Indifferent.esp
  wrote patch part Requiem for the Indifferent 2.esp
  ...
  The patch was split into N plugins due to the master list limit.

ВАЖНО: после разбиения ВСЕ части должны быть включены в порядок
загрузки:
  - части ставятся подряд в числовом порядке
    (основная часть, затем ... 2.esp, 3.esp и т.д.);
  - все части идут ПОСЛЕ остальных модов;
  - основная часть "Requiem for the Indifferent.esp" остаётся там же,
    где была раньше, существующий порядок загрузки менять не нужно.

ПОСЛЕ РАЗБИЕНИЯ - ЧЕКЛИСТ ПО УБОРКЕ (прочитайте!)
-------------------------------------------------
1. ГДЕ ЛЕЖАТ ЧАСТИ? Основная часть записывается в ту же папку мода,
   где уже лежал старый патч (MO2 перезаписывает существующий файл).
   Дополнительные части (Requiem for the Indifferent 2.esp, 3.esp...) —
   это НОВЫЕ имена файлов, поэтому VFS MO2 кладёт их в папку
   "overwrite". Перенесите каждую дополнительную часть из overwrite
   в ТОТ ЖЕ мод, что и основная часть, иначе части могут исчезнуть
   при следующей очистке overwrite.

2. УДАЛИТЕ УСТАРЕВШИЕ КОПИИ. Если файл "Requiem for the Indifferent.esp"
   лежит сразу в нескольких модах (старые бэкапы, старые версии
   патча), MO2 загрузит только копию из мода с НАИВЫСШИМ приоритетом —
   и это может оказаться СТАРЫЙ битый патч, поверх которого лягут
   новые части 2/3. Результат — несогласованные данные патча и
   ошибки вида "Requiem не смог инициализировать все основные
   скрипты". Держите новый патч ровно в ОДНОМ моде, а все остальные
   копии переименуйте (например, в .esp.old), чтобы они не
   загружались.

3. ПРОВЕРЬТЕ ПОРЯДОК. После переноса частей в порядке загрузки должно
   быть:
       Requiem for the Indifferent.esp
       Requiem for the Indifferent 2.esp
       Requiem for the Indifferent 3.esp   (если есть)
   подряд, друг за другом. Запустите LOOT, затем убедитесь, что
   части не разъехались.

4. НАЧНИТЕ НОВУЮ ИГРУ после перепатча. Requiem проверяет патч при
   старте сохранения; сохранение, сделанное при другой раскладке
   патча, может не пройти инициализацию core-скриптов.

ИСХОДНЫКИ
---------
Папка Source\ содержит полный исходный код с внесёнными изменениями
(файлы PatchSplitter.cs и Backend.cs). Сборка: .NET SDK 5+,
`dotnet publish -c Release -r win-x64 --self-contained true`.

ОГРАНИЧЕНИЯ
-----------
- Разбиение срабатывает только при превышении лимита; обычная работа
  не меняется.
- Если один только "новый" контент патча (глобальные переменные,
  списки форм, новые записи) ссылается больше чем на 250 модов,
  разбиение не поможет — в этом случае уменьшите загрузку.
